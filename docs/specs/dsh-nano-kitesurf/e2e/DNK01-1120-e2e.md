## 0. 边界（先读）

[业主] 于本轮指定：**DNLS 由另一工作树 `.agents/worktrees/dnls03-managed-sandbox-control` 独占升级，本工作树不得修改其代码、不以其测试为准**。因此：

- 本册只验收 **DNK 侧**（pane 渲染面、design mode、devtools、HITL 界面、skill）。
- `T-O-1`（宿主 `sandbox.open`）、`T-O-2`/`T-O-3` 的**协议半段**（桥 `relay` 字段与 relay 写拒绝）、`T-O-5`（`/res`）、`T-O-6`（`/open` 与 `/res` 的 tunnel hint）都在 DNLS 包内 → **本轮不实现、不验收**，见 §4。
- 生产侧 DNLS 是**旧版**（无 `networking`、无 `/res`）。本册把「DNK 在旧 DNLS 上仍然可用」当作**韧性**证据，而不是缺陷。

## 5. 结论

- **Q1（agent 打不开页）**：DNK 侧闭合——skill 可加载 + 如实写明 `/open` 的鉴权边界 + relay 是 agent 的打开面；宿主侧一键工具在 DNLS 车道。
- **Q2（relay 无提示）**：DNK 侧 UI 与降级闭合；数据源在 DNLS 车道。
- **Q3（接管拦不住 agent）**：MCP 写路径已闭合且 A 级验证；relay 写路径在 DNLS 车道。
- **Q4（design mode 选不中 / 无样式）**：**闭合**——默认引擎渲染 + 坐标点选 + 写回，全部 A 级，且在**旧版 DNLS** 上成立。
- **一处被实测纠正的判断（E15）**：我原先在 HTML 模式前写了「会丢外链样式」，实测该站样样式正常。已把文案改为只陈述「宿主未声明同源代理」这一事实，并给出条件化建议；不把「可能」写成「必然」。
- 生产实例已跑本分支 HEAD，页面、pane、skill 三面均验证通过。
