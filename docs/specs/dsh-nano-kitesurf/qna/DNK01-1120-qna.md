## 3. 逐题裁决

> 每题保留提问时的选项（provenance），裁决结果与冻结后的权威文本以 §1 为准。

### Q1 — agent 的「打开页面」面放在哪里？

**断点**：skill 加载失败（`resourceBase`）→ 拿不到 relay 知识；`POST /open` 需 GUI cookie（实测 **401**）；桥**没有**导航工具（`mcp-bridge:484-579`）。三者叠加后 agent 只剩裸 CDP，而裸 CDP 连 `:8798` 会造私有页。

| 选项 | 内容 | 评价 |
|---|---|---|
| **A** | 新增 MCP 工具 `sandbox.open {url}`，与 `POST /open` 共享内核；鉴权沿用宿主 MCP 既有准入，不新开凭证面 | 一条与人等价的打开面；不扩大信任边界 |
| B | 放松 `/open`：无 cookie 的本机请求放行 | 等于拆掉 `route-guard:204` 那条边界，所有路由一起失守 |
| C | 不加工具，只修 skill，让 agent 裸发 `Page.navigate` | 没解决「打开」这个动作的语义；错误分类、审计、hint 全拿不到 |

**裁决（[业主]，2026-11-20）：A。** 冻结为 `T-O-1`。冻结时补正：内核是 `openPage(session,url)`（`/open` 现为内联分支，`F7`）；该工具必须计入 `isWriteCall()`（`F3`）。

### Q2 — relay 接入如何让人看见？

**断点**：`makeCdpRelay`（`:199`）零处引用 `control`；`lastAction/lastCallAt` 只由 MCP 写更新；控制条只读 `humanHold||writer`（`client:2788`）。→ agent 用 relay 驱动页面时**界面上没有任何归属信息**。

| 选项 | 内容 | 评价 |
|---|---|---|
| **A** | `/control` 增只读 `relay:{conns,lastAt,lastMethod}`；控制条条件扩为含 relay | 最小可观测面，不改写权语义 |
| B | 只在 `/health` 加计数 | 人要主动开诊断页才看得到，等于没解决 |
| C | 不改 | Q2 未闭合 |

**裁决（[业主]，2026-11-20）：A。** 冻结为 `T-O-2`，并明确「新增只读字段本身构成扩约」已获批准。冻结时补正：`conns>0` 恒真会导致长期误显示「正在操作」（`F6`）→ 改两档语义；`lastMethod` 只存方法名（`F12`）。

### Q3 — 人的接管要不要真能拦住 relay？

**断点**：`humanHold` 的拒绝只在 `isWriteCall` 分支（`mcp-bridge:902`），**只覆盖 MCP**；relay 的 `Page.navigate` 完全绕过。→ 后果不是「agent 不能操作」，而是**人不能拒绝 agent 操作**，「停止写入」是空承诺。

| 选项 | 内容 | 评价 |
|---|---|---|
| **A** | `humanHold.active` 时拦 relay 的写类命令，先记 `lastAction` 再回 CDP error；读类不拦；pane 给可见回执 | 让「接管」在**所有写路**上成立 |
| B | 只记录不拦截 | 可观测但不可拒，Q3 只解一半 |
| C | 不覆盖 relay，只在 skill 里写明 | 把风险留给使用者 |

**裁决（[业主]，2026-11-20）：A。** 冻结为 `T-O-3`，写入承诺的变更（relay 从「不受限」变为「可被拦」）已获批准。冻结时补正：拦截面限定 agent 主体、不锁人在 pane 上的动作（`F4`）；`Runtime.evaluate` 读写不可区分故全拦（`F5`）。

### Q4 — 渲染面默认与 `/dom` 版本字段

**事实**：默认 HTML（`976b393`）使本地 http 站必然无样式（混合内容），用户看到的「design mode 选不中元素」是其后果；`6388023` 已把默认改回引擎渲染，并给 HTML 模式加同源代理（`dom-srcdoc:106`）。

| 选项 | 内容 | 评价 |
|---|---|---|
| **A** | 冻结「默认引擎渲染 + HTML 模式经 `/res`」；并把 `/dom` 版本语义收归宿主 | 一次定死两件事 |
| B | 只冻结渲染策略，`/dom` 字段不动 | 渲染闭合，但（当时认为的）抖动仍在 |
| C | 回退「HTML 为默认」 | 与既有裁决相反 |

**裁决（[业主]，2026-11-20）：A。** 冻结为 `T-O-4`。冻结时补正：**A 中「收归宿主」的部分已经成立**（`F1`）——宿主早有 `domSeq`/`capturedAt`，客户端早已优先使用；因此本条登记为**现状冻结**，不新增 `/dom` 字段、不改语义。同时登记 `T-O-4` 依赖 `T-O-5` 的公网范围（`F2`）。

### Q5 — `/res` 的放行范围与边界

| 选项 | 内容 | 评价 |
|---|---|---|
| **A** | 放行任意 `http`/`https` + 硬边界（无凭据、≤24 MiB、15 s、剥 `Set-Cookie`/CSP/`X-Frame-Options`、重定向回代理空间、具名 errorId） | design mode 需要外链 CSS/字体（该站实测引 `fonts.googleapis.com`） |
| B | 仅私网 / `networking.hostGateway` | 与 `T-O-4` 互斥（`F2`）：会破**全部**外链资源，不只混合内容 |
| C | 任意外网 + 二次开关 | 多一个状态位与心智负担，收益不明 |

**裁决（[业主]，2026-11-20）：A。** 冻结为 `T-O-5`。冻结时补正：登记两条互斥关系与「https 页也走代理」这一已知取舍。

### Q6 — 公网隧道怎么「禁」？

**背景**：[业主] 已定性「cloudflared 是完全错误的行为，绕过全部拓扑」，同时要求「禁止的工作要用 error 禁止」。

| 选项 | 内容 | 评价 |
|---|---|---|
| **A** | **警示而非阻断**：命中已知隧道域附 `hint` + 具名 id，`/diagnostics` 同源提示；skill 禁令表已落（`recipes.md` 配方 5） | 域名黑名单脆弱且会误伤合法站；警示能把人和 agent 拉回正确路径 |
| B | 硬拒绝（502/400） | 语义最强，但需同时批准「需持续维护的清单」作为配置面 |
| C | 只在 skill 里写禁令，代码不检测 | 已证明不够：那条 session 的 agent 自己起了 tunnel |

**裁决（[业主]，2026-11-20）：A。** 冻结为 `T-O-6`。冻结时补正：明确它们是 **hint code 而非 error 枚举项**（`F10`），并显式登记这是对「用 error 禁止」的**有意偏离**及改回条件（`F11`）。
