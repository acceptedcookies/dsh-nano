# [DNLS] 受管对象合同切换

本指南面向原先按 session 操作本地沙箱的操作者和客户端作者。`dnls.control/1` 是控制合同版本，不是 npm 包版本。提供者和消费端要配对升级；[DNT] local 与第三方 MCP 不使用这套迁移规则。

1. **先确认环境。** 每个 `DSH_HOME` 使用自己的状态根。已有卷但没有对应台账、台账损坏或版本未知时，宿主拒绝初始化；不要清空目录、删锁或按容器名推断归属。保留原卷和台账备份，在接管手续完成前保持旧对象不受管。新建对象不是迁移旧卷。
2. **先发现，再选定。** 在已获准的当前宿主读取 `GET /nano-local-sandbox/contract`。响应头与正文必须都是 `dnls.control/1`。MCP 调 `sandbox.contract`。列出可见对象，明确选择 `sandboxId`；不能从 session、容器名、当前 pane 或相邻端口推算。
3. **保存操作引用。** 对象 HTTP 请求带 `X-DNLS-Contract: dnls.control/1` 和一个 query `sandboxId`；MCP 在 `params._meta["dnls/contract"]` 配对版本，仅在 `arguments.sandboxId` 传目标。首次创建不传已有目标。提交后保留原 `requestId`、`operationId` 与 `sandboxId`；202 只是受理。断线时查询原操作，不换键重发。`indeterminate` 需要核对现场。
4. **终端分两次操作。** 只在明确新建时用 `paneId/openId` 调 `term.session.create`；返回两个 ID 而不返回地址。授权的 `term.session.list` 可给出已有终端的资源引用。该引用不是 bearer，也不是 WebSocket 地址。重新打开只走 `term.session.attach`，使用核权后的 `dnt-ws-v2` locator，不重发输入、不创建第二个终端。关闭页面只 detach；结束 PTY 是单独的显式动作。
5. **核对宿主依赖。** 共享 browser owner 不证明终端的个人归属。没有可信的细粒度主体时，不调用 broker，也不会发出地址。当前右侧工作区的页签需要已挂载的 session；这不是无 session 管理页。使用有权的公开管理 API，不用本机 shell、假 session 或旧 v1 地址补位。

停止 sandbox 保留其 ID、端口、卷与名额。保存资源期望不自动应用；显式换代前核对修订、保卷和终端中断影响。升级失败时保留原始文件和操作回执，停止写入；旧提供者不理解新台账，不能作为自动回退路径。

### 在工作台管理沙箱

在 session 的「沙箱」页签按运行、停止或需要关注筛选，再点对象名。每行的 CPU 和内存是上一完整 UTC 分钟的用量 / 已验证的分配量，不是整台 Mac 的读数。横线表示没有观测；零是有效读数。停止对象仍占名额，查看列表不会唤醒对象、读取来宾进程或新建终端。

顶部状态条标明当前对象和环境。资源监控支持 24 小时、7 天和 30 天；展开「来宾进程」才会读取，初始按 RSS 降序，可点列标题换序。「服务与工具」查看发布、探针、日志和授权终端。点状态条的返回键从工具回到监控，再次返回回到原筛选列表。

齿轮打开此对象的设置。CPU 和内存保存为期望配置，保存不部署；闲置策略单独保存。展开危险区才出现重建和移除，二者都需单独确认。关闭弹窗不提交表单。

现有 `dnls.control/1` 的只读响应增加可选字段：窄行的 `resources` 是实测配置量；仅已获准的对象所有者兼操作者能看到 `lastMinute`。同一权限下的 `usage.history` 最多有 36 个按 UTC 排列的分段；`at` 是起始毫秒，`minutes` 是段长，`cpuValid` 和 `memoryValid` 是各自覆盖的分钟数。分段的 `cpuCores` 为按实测时长加权的均值，`memoryBytes` 为有效读数的均值；没有读数是 `null`，不是 0。时间窗的均值和峰值来自原始分钟，不从图表反推。不新增端点，不迁移台账或卷。

## 为控制面接入其他后端

`dnls.control/1`、对象 ID 和既有台账不因本次适配变化而升级。UI 消费宿主公告的能力与对象投影，不消费 CLI JSON。实现新后端时注意：

| 后端交给控制内核什么 | 内核据此能做什么 |
|---|---|
| `observe(locator, {stateTarget})`：同一绑定的代次、状态、挂载、资源及实际发布元组 | 只在代次和卷都核实后操作。明确证实不存在才返回 `state: 'missing'`；读失败或歧义不能当成不存在 |
| `createManaged(spec)`：接收 CPU、内存字节、结构化挂载与发布元组，另以 `imageEvidence` 核镜像 | 先记持久意图，后派发，并以新的独立观察核实结果。Apple 的参数拼装、创建时间解释和代次算法均是适配器职责 |
| `sampleUsage(locator)`：返回对应对象的内存字节和累计 CPU 微秒 | 分钟采样保留零和缺样的区别，只在连续的同代次片段计算 CPU |
| `capabilities()` 及对应方法 | 发现和派发按动作判断。只有 stop 的实现不应为了点亮 restart 而声明 start。NVX 当前不提供执行能力 |

切换页面表示法并不扩大权限。个人终端资源引用不能替代 attach 授权；workerd 进程读数不是独立服务重启能力。服务端未给出的健康、配额、版本或用量都不是零，也不代表正常。
