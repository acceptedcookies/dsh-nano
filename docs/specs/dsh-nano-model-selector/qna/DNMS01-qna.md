**【对本问题的解读】**

1. 本问裁决的不是「用哪个类名」，而是 **「compaction lane 在 ON / OFF 两态各归谁，以及这个归属怎么切」**。类名、模块划分、状态文件字段都是同一决定下的实现细节；真正要冻结的是**双态权威边界**与**切换层级**。
2. 「替换全部压缩的真源」在 `T-O-DNMS01-2` / `-9` 下必须读作：**ON 态**替换压缩的策略 / 配置 / 触发 / backend 真源；**OFF 态**把该权威**归还 [dsh] 原生**。Session log 在两态都是 host-owned 的会话 durable 真值，插件在任何一态都不复制它。
3. **「硬切」在本问里的三个可验收含义（v0.2.0 重定义）**：① 任一瞬时**恰好一个** active `ctx.compaction` provider，切换**原子、无重叠**；② 两态都不出现第二份可写 config、不出现状态双写、不出现 `/compact` 双路径；③「彻底退役」的对象是**合同面**——旧别名、旧配置键、兼容转发层、架构 B 的静默降级——**不是出厂 backend 本身**；出厂 backend 是**挂起可恢复**。
4. **「并存」与「互斥」必须分开**（v0.1.0-draft 的错误就在这里）：并存 = 两个 provider 同时 active、双写、别名、façade（对应原选项 C，仍不推荐）；互斥 = 组合树里两行都在、但任一瞬时只有一个 enabled（本问选项 A）。`compaction.md:147` 的「one implementation」否掉的是前者，不是后者。
5. **「切换」不是「运行期服务值开关」**：`ctx.set` 只有提供该服务的 fiber 能用（`context.md:267-268`），`ctx.provide` 同名 throw（`:294-295`）；合法路径是 Loader 在 **mount decision** 重算 `disabled`（`composition-reference.md:16`、`cordis-primer.md:39`），由 `set_plugin` / HMR `reconcileProfile` 触发一次重组合（`plugin-manager/src/index.ts:929-938,1349-1358`），旧 fiber 先停、新代再应用（`app-boot/src/index.ts:384-392`）。**写 `async-compact.json` 的 `enabled` 本身不会翻转 `disabled`。**
6. **必须成对翻转并覆盖全部作用域**：只关我方行、出厂行仍 `disabled:true` → 该 realm 无任何 `ctx.compaction`，`/compact` 直接失败（`compaction/README.md:47`）；且 web profile 的三条 base 扁平行已被 `web-app/cordis.patch.yml:576-583` 禁用，真 provider 在 4 个 preset group 内，只改 base 会漏。
7. 与要求 ④ 的边界：micro 不接管 = `dsh-compaction-tool-result-pruner` **行始终挂载、行为不变**（其 `toolResultPruner` 是独立 isolate realm，不受 compaction 翻转影响）；full 作兜底并接入 = `dsh-command-compact` 始终保留（`:358-359` 注释明写 backend-independent，会跟随当前 active Provider），ON 态 S 线 / overflow 的阻塞 full 由我方 Provider 实现，OFF 态由原生 `agent/request-error` recovery 承担。这两条是**保留项**，不是兼容层。
8. Q1 与 Q2 同轮并行、均由 baseline 驱动；Q2 不依赖 Q1 的裁决结果。若 [业主] 在 Q1 选了非 A，Q2 的选项空间需在**同一轮内**重开（不跨轮预设），并在 §3 中场评估里登记。

**【对本问题的解读】**

1. 本问裁决的不是「UI 开关怎么画」，而是 **「ON/OFF 这个布尔本身在系统里住哪、有几份可写副本」**。`-10` 已冻结「怎么切」、`-11` 已冻结「策略数据住哪」；本问补的是**切换状态**这一格，三者合起来才是完整的真相拓扑。
2. **「两态各一份 canonical」（`-11`）不等于「开关状态可以两份」**：ON/OFF 是跨越两态的**同一个决定**。`-11` 的两份分别服务于「ON 态策略」与「OFF 态原生 Config」，互不重叠；而 `enabled` 字段与 profile `disabled` 描述的是**同一个布尔**，且都可写 —— 这才是被 `AGENTS.md:39` 禁止的双写。
3. **「拒绝 hotfix」在本问的具体含义**：不为「json 写了但 runtime 没切」加一个运行期补救/仲裁循环；不引入「启动 reconcile 一次」这类顺序决定真值的窗口；不把 `enabled` 保留成「以后可能有用」的兼容键。开关只由 `-10` 冻结的组合层路径写一次、读一次。
4. **「能彻底退役就不要提供兼容」在本问的具体含义**：`enabled` 字段、`enabled=false → 宿主默认压缩` 这句草案说明（[`async-compaction.md:433`](../async-compaction.md#L433)）、以及任何「json 优先 / patch 优先」的映射，一并退役；不保留旧键回退、不保留双读。
5. **bundle 级开关不是本题答案**：`set_bundle` 改的是 `package.json` 的 `dsh.profile.bundles`（`plugin-manager/src/index.ts:1286-1289`），整包禁用会连 `conversation.input.model` 座位注册与设置按钮一起移除（`[DNMS]/src/client/index.jsx:24`）——粒度错，列为选项 E 反例。
6. **本题不重开 Q1/Q2**：不改 `-10` 的成对翻转 / HMR 边界，不改 `-11` 的「ON 态状态文件唯一可写、OFF 态插件零写」；只删 `-11` schema 中与开关状态重复的 `enabled` 字段，并以 R-7 留痕。Q1 附带裁决（触发层级）仍按 `-10` 末句留 executional 轮。
7. Q3 与 Q4 同轮并行、均由 §1 已冻结真相驱动；Q4 不依赖 Q3 的裁决结果。若 [业主] 在 Q3 选了非 A，Q4 的选项空间需在**同一轮内**重开并在 §5 登记，不跨轮预设。

**【对本问题的解读】**

1. 本问裁决的不是「full 的 prompt 怎么写」，而是 **「要求 ④ 在 `-10` 的 ON 态拓扑里落到哪一层」**。`-10` 已让我方成为唯一 Provider；既然只有一个 Provider，full 就只能是它的内部模式，micro 就只能是「不被提供、但可被消费」的兄弟服务。
2. **「不接管 micro」的精确边界（本轮代码调查给出）**：[dsh] 里没有独立的 micro 命令 / lane；`tool-result-pruner` 是 `super(ctx,'toolResultPruner')` 的可选服务，由 compaction backend 在**同一次策略调用**、trigger qualify **之后**、写 `compaction/start` **之前**调用，随后 `meter.measure()` 重测，若已低于阈值可直接结束而不写摘要（`compaction-basic/src/index.ts:344-350`；`compaction.md:101`）。因此「零改动」指行 / Config / 服务实例 / 触发时机，**不指「不调用」**；不调用反而丢失 model-free 泄压与 `replaceGeneration` 重试凭据（`:235-241`），是新的 hotfix 式偏离。
3. **「拒绝 hotfix」在本问的具体含义**：full 不塞进同步 swap 路径、不另开旁路、不在 ON 态留原生 backend 兜底、不把 overflow 恢复写成临时补丁；三个方法按抽象类契约一次性实现完整，失败走既有六个 typed 失败码与 `compaction/summary-error` waterfall。
4. **「能硬切就不要双写 / 能彻底退役就不要提供兼容」在本问的具体含义**：不留第二个 `ctx.compaction` 提供者、不投影第二份 Config、不留 `/compact` 双路径、不保留原生 `compactionRetries`/`maxOverflowRetries`/`auto` 的半活状态——ON 态这些语义**全部由我方自持**，OFF 态**全部归还原生**（`-9`、`-10`）。出厂 `maxTokens` 是明确例外：no-cap 要求省略输出上限，不能照抄（[`async-compaction.md:233`](../async-compaction.md#L233)）。
5. **草案矛盾必须显式修掉，不得由实现反推合同**（`AGENTS.md:40`）：`async-compaction.md:359/:519` 与 `:335/:502` 对 overflow 归属冲突、`:492`「P3 冻结」标题与 `:328` 待裁决槽冲突（`-8`）。本问裁决后，§5 收口时以 R-8 登记这些草案语句被冻结真相 supersede。
6. **本题不预设 executional**：具体 B/H/S/pinned 默认数值、等价于 `maxOverflowRetries` 的取值、prune 是否在 B/async 线触发、三方法的具体实现与失败码映射、验收矩阵 —— 全部留 executional 轮。本问只冻结**归属拓扑与触发闭集**。
