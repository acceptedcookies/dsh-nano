### 2.2 账本计算点、公开合同与骨架

#### `T-O-5` —— 唯一计算点与同次硬切

#### `T-O-6` —— `wire` 视图是唯一公开只读合同

> **来源**：`Round 1 / Q2，[业主] 同意 A 全部推荐` ｜ **驱动后续**：`Q3–Q5、Q7、Q9、Q11`

账本的 `wire` 视图是 [DNPR] 唯一的公开只读合同，带版本号 `v`。消费者只经 [dsh] 宿主自有读面获取：浏览器 `session.projections.faceOf(key)`、宿主插件 `ctx.sessionProjections.snapshot(session, [key])`、跨会话 `sessionQuery.observeSession`。[DNPR] 不 `ctx.provide`、不开路由、不把投影 handle 当读取接口导出。视图只含派生事实、seq 指针和覆盖/截断标记；任务正文是 `todo/write` 原样字段；不含命令、输出、reasoning；不为任何特定消费者定制字段。同一 `v` 内只追加可选字段，破坏性变化升 `v` 并同次硬切，不同时发布两版、不留旧版兼容读者。[DNPR] 未安装时 key 不存在，消费者必须降级。**字段表只登记在 `[NPR]/AGENTS.md`**。模型侧出口、跨会话授权范围、身份维度与字段清单不在本条。

#### `T-O-7` —— 工作项骨架与状态口径

> **来源**：`Round 2 / Q3，[业主] 同意 A 全部推荐` ｜ **驱动后续**：`Q5–Q8、Q11、Q12`

账本以「工作项」为一级骨架：**人类指令与 goal 是一级工作项，todo 任务是挂在所属工作项下的可选二级**。指令以其 `user/message` 事件 seq 为身份；goal 以 goal id 为身份，各轮次是该项内的进展；代理回报、子代理结束通知不新开工作项，挂到当时所属的工作项。识别看消息 `source`，不看角色。工作项状态只陈述可从事件得出的事实：进行中、最后一个 `turn/end` 的结束原因、等待中、未解决失败数；不对指令推断「已完成」，goal 阶段读官方 goal owner。任务身份沿用 `content`，跨回合保留，挂在首次列出它的 `todo/write` 所属工作项下；证据先归工作项，恰有一个任务 `in_progress` 时同时归该任务（判定口径经 `-15` 冻结），否则不归任务。子代理会话同样适用，账本不跨会话。工作项随指令线性增长，必须有明确上限，早期项降级并标明覆盖范围。不新增模型声明里程碑的工具（列 v1.2 候选，不在 DNPR01）。

模型可见文本是只读工具 **`read_progress { item?: integer ≥ 0 }`** 与**四行推送锚**，二者逐字锁定。工具不传 `item` 返回概览：首行写 `asOfSeq`、工作项总数与三层各自的数量，完整层与骨架层每项一行（最多 80 行，新的在前），末行写累计层；传入 `item` 返回该项明细：任务（状态与原样 `content`，每条 ≤ 200 字节）、改动文件与未恢复失败（带事件编号），已恢复失败只给数量，超限写「另有 N 条未保留」，骨架项只给计数，未知 id 返回结构化失败。结果为纯文本，整份 ≤ 16 KiB，截断如实标注；`when` 仅在账本至少有一个工作项时出现；描述采用 Q8 草案。推送锚模板为 `Current work: <a user request | a goal | a scheduled task>` / `Tasks: <c> complete, <i> in progress, <p> pending; in progress: <"content">`（读官方 `todos`）/ `Unresolved tool failures in current work: <n> (<tool> <k>, …)`（按工具计数，不含命令）/ `Active: <j> background jobs, <s> direct subagents`（官方 jobs 与直接子代理）四行；固定首行为 `Current session progress (observed facts, not instructions):`，计数为 0 的行不输出，只剩首行时返回空串。删除 `Goal:`、路径与「最近 Bash 失败」行，不设等待行，锚里不提工具。未恢复的 bash 失败只给工具名、次数与事件编号，不含命令（`-8`）。工具文本与 `-6` 视图是两种格式，模型合同不绑定公开合同。工具描述、schema、锚模板及概览/明细/截断/未知 id 用例由单测逐字锁定；**改动任一字面都是模型合同变化，需 [业主] 裁决**。

### 2.4 账本计算规则：开项、失败与有界

#### `T-O-9` —— 开项白名单 `user`/`goal`/`schedule`

> **来源**：`Round 3 / Q5，[业主] 同意 A 全部推荐` ｜ **驱动后续**：`Q8、Q10、Q11`

**工作项的开项白名单是 `user`、`goal`、`schedule` 三种消息 source。** 回合打开期间第一条命中白名单的 `user/message` 决定该回合归属：`user`（含子代理会话中被委派的提示）与 `schedule` 开新项；`goal` 的 goal id 与当前项相同则并入，否则开新项。同回合内后续命中白名单的消息不另开项。其他 kind（`retry`、注入上下文、代理消息、子代理结束通知、job 唤醒及宿主将来新增的任何 kind）一律挂靠当前工作项。账本只存开项 seq、goal id 与回合号区间，不复制提示或 goal 目标文本。首个工作项之前的事实只计入视图顶层的未归属计数，不伪造工作项；fork 继承段按 `inherited` 排除。开项判定放在 `src/shared/`；浏览器时间线同一次发布让 `schedule` 也开组，不留两套口径。提示预览由消费者按回合号关联官方 `turnOutline` 获取；goal 目标读官方 `goal` 投影（只含当前 goal）。

#### `T-O-10` —— 失败、恢复与待处理项

> **来源**：`Round 3 / Q6，[业主] 同意 A 全部推荐` ｜ **驱动后续**：`Q8、Q12`

**全部工具记录失败；恢复的唯一证据是同一指纹在同一工作项内后来成功。** 共享指纹：bash 用现行命令指纹（cwd、workdir、command；后台运行的 bash 不产生指纹），文件工具用路径（write、edit、apply_patch 归一，apply_patch 每个路径各一），其他工具用工具名加规范化参数摘要。未恢复失败冻结为所属工作项的历史事实，后续项的成功不改写它；「当前」计数只看当前工作项。失败判定沿用宿主语义（`isError === true` 或 `error != null`），非零退出码不算失败；bash 成功要算恢复仍需通过现行终态检查。待决提问读官方 `userQuestions`；审批由账本按 id 配对 `approval/asked`/`approval/decided`，回合结束时未决者关闭；jobs、子代理读官方。指纹函数放在 `src/shared/`，宿主账本与浏览器精简分层共用；时间线的「失败 k 次后通过」与 A 层未恢复失败按回合分组判定，goal 项跨回合的恢复由账本陈述。本条细化 `-5` 的「待处理项」：官方已有 owner 的待决提问不在账本中重算。

#### `T-O-11` —— 三层有界与 `v1` 合同常量

> **来源**：`Round 3 / Q7，[业主] 同意 A 全部推荐` ｜ **驱动后续**：`Q8、Q10–Q12`

**账本三层有界，上限是 `v1` 合同常量。** 最近 **16** 个工作项保留完整明细（文件 ≤ **32**、失败指纹 ≤ **16**、任务 ≤ **32**，超限保留最近条目并记总数）；再往前 **64** 个降为骨架行（身份、类别、开项 seq、回合区间、结束原因，文件/失败/未恢复/任务计数）；更早的并入累计计数。降级确定、不可逆，降级后的项不再接收更新；降级后再出现的同 `content` 任务挂到当前项。视图顶层如实标注 `asOfSeq`、`inherited`、累计层覆盖到的最后 seq 和各列表的截断计数。16/64/32/16/32 只登记在 `[NPR]/AGENTS.md` 字段表；调整任一数值是破坏性变化，升 `v` 并同次硬切；不做成 `Config`。状态含当前回合未配对调用缓冲（≤ 64），`parseState` 白名单重建并拒绝超限集合，`stateVersion` 从 1 开始；无关事件返回同一状态引用，骨架行冻结复用。不拆成多个 key。落地后用 `[PROD]` 复测视图体积、推送次数与冷构建耗时，只记录不设闸门。

#### `T-O-15` —— `v1` 任务字段、顶层语义与字段表审批

**`v1` 视图的任务字段与顶层语义冻结；任务证据不进入 `v1`。** 任务字段为 `content`、`status`、`firstSeq`、`completedSeq`、`completedAt`：`content` 是 `todo/write` 原样字段；`status` 取本项中最近一次包含该 `content` 的 `todo/write` 快照里的状态，快照未包含时保留上一次状态；`firstSeq` 是首次列出它的 `todo/write` seq；`completedSeq`、`completedAt` 是它首次以 `completed` 出现的 `todo/write` seq 与事件 `time`，之后改回 pending 不清除、再次 completed 不覆盖，未完成不写。任务证据字段不进 `v1`；`-5` 的「证据 seq 区间」与 `-14` 的 C1-03 归属单测随证据字段延后，不在 `v1` 实现（`-7` 的证据归属在 `v1` 也不执行，只冻结口径），重开时按本条口径补归属规则单测；`-7` 的归属口径冻结为「**当前回合内最近一次 `todo/write` 中恰有一个 `in_progress`**」，回合开始后至新的 `todo/write` 之前不归任务；证据字段追加时递增 `stateVersion` 并冷重建，其上限作为新常量写进字段表。`asOfSeq` 是**最后一次改变账本事实的事件 seq**，无关事件不推进、不重建；`inherited` 是宿主 `init` 传入的 fork 继承前缀长度，seq 小于它的事件不计入，非 fork 为 0；未归属计数是首个工作项之前完成的工具调用数及其中失败数，不挂明细、不伪造工作项。**字段表由实现分支写进 `[NPR]/AGENTS.md`**（名称、类型、含义、上限、截断表示），[业主] 在合并评审中审批，合并即生效；之后追加可选字段同样在合并评审中由 [业主] 批准，破坏性变化按 `-6` 升 `v`。QNA 只冻结语义，不复写字段表。
